Environment: GitHub Actions Ubuntu runner, Node 24, headless Chromium 153, 800×600 canvas.

**Important:** this environment uses virtual/software graphics. These numbers are useful for relative scaling and for finding where a library falls out of a frame budget, but they are **not** a low-end Android hardware benchmark.

## What this says about KAPLAY

For ordinary Kakkoi School games, KAPLAY 4000's older reputation for collapsing under modest object counts is **not reproduced here**:

- 500 moving objects: well inside a 16.7 ms / 60-fps budget.
- 1,000 moving objects: still inside budget, including with `area()`.
- 5,000 moving full game objects: no longer acceptable for a 60-fps target.
- 5,000 objects with `area()`: particularly expensive.

So the practical rule should be:

> KAPLAY is reasonable for normal student games. Do not represent thousands of particles, decorative tiles, or background elements as full KAPLAY game objects with collision areas. Batch/direct-draw those cases.

## Why Kontra looks dramatically faster

Kontra is much thinner and the benchmark uses its normal Canvas2D sprite path. KAPLAY and LittleJS include substantially more engine machinery and use different rendering architecture. This table therefore should **not** be interpreted as “Kontra is 80× faster on a phone.”

It does show that Kontra has very low framework overhead for this exact simple workload.

## LittleJS caveat

LittleJS targets a fixed 60 Hz game loop in this benchmark, so the <=1,000-object rows are effectively capped around 60 fps and cannot be compared numerically with the uncapped KAPLAY/Kontra rows. The useful signal is that it holds its 60 Hz target through 1,000 objects and falls to about 27 fps at 5,000.

## Decision status

Do **not** choose the official Kakkoi School library from this CI result alone.

The next useful test is the same benchmark on a real lower-end Android browser. Until then:

- **KAPLAY 4000**: strongest beginner/AI API, acceptable scaling up to the student-game range in CI.
- **Kontra**: lowest overhead and simplest engine layer.
- **LittleJS**: capable middle ground with a 60 Hz-oriented engine architecture.
